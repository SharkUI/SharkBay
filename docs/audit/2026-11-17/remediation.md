# 修复与质量提升路线

基线 `2fc9c93`。本次交付审计报告，不在审计过程中混入产品修复。按以下批次处理，每批绑定问题、最小变更、回归与指标，保留现有功能。

## 第一批 数据与共享进程风险

- UI-06：区分文件 create/save，创建使用后端原子 exclusive 语义。验收同名与并发创建不改变旧文件字节，编辑保存继续可用。
- SD2：统一内部受管理路径的安全解析和 taskId 格式验证。验收临时链接、父目录与文件替换、非法 taskId、普通合法任务均符合边界。
- UI-01、RL3：异步副作用局部捕获错误，usage 成功提交后再移除批次。注入失败后进程继续可用、事件可以重试且不重复计数，错误不吞没。
- SD1：明确 LAN 信任政策；建议默认 loopback，远程采用独立可撤销授权。该项涉及有意设计，应先确定访问契约，再实现并验收合法与非法客户端。

## 第二批 并发 取消与会话归属

- RL1/RL2：移出占槽任务内的嵌套刷新，定义 deadline、实际停止、槽位和 dispose 契约。用两个 fake 安装、取消失败和迟到结果验证无互相等待、无残留工作超并发。
- UI-02 至 UI-05：审批绑定原请求、列表按用户和消息隔离、poll generation 可取消、PTY 控制与订阅归属统一。验证双用户、多会话、迟到回调、快速启停及撤销。
- RL4/RL5：信号退出明确失败，禁用索引先取消并等待再卸载。验证 fake CLI 的 sync/uninit 不重叠，取消后状态与磁盘投影一致。

## 第三批 Git 协议 投影与日常可靠性

- SD3：通过 Git 自身解析 gitfile/worktree 元数据位置，部分安装状态准确报告或回滚；普通和 linked worktree 的完整协议生命周期均需回归。
- SD4：成功完整读取远端后更新镜像，失败保持最后成功投影并标 stale；删除与重命名准确反映，本地未同步数据保留。
- SD5：使用 NUL 分隔 Git 状态协议，覆盖中文、控制字符、rename/copy 和字面箭头。
- RL6/RL7 及后续独立确认项：插件启停失效相应缓存，修正机器字段和 shell 发现契约，避免把尚无生产入口的 project profile 当成当前 UI 性能路径。

## 第四批 性能 结构与遗留治理

- UI-07：对 transcript 支持和原始 PTY fallback 分别设定缓冲用途与字节上限。固定输出增长时缓冲达到上限，正确保留必要尾部并提示截断。
- 明确 watcher 文件状态、usage 去重、profile cache 的保留期与淘汰策略；记录扫描量、排队时间、真实任务时长和 deadline，先测量再优化。
- UI-08、QB-02/QB-03 等候选：判定生产契约与兼容用途后小批清理；不为了接通无用机制而增加新的功能。
- App、harness、Telegram 的拆分以命令、状态与资源所有权为界，逐项降低重复规则和隐式同步；不按行数进行无验收的大规模重写。

## 第五批 测试 文档与发布防线

- 依据测试专项将真实机器探测单列环境测试；fixture 统一释放，异步存储 teardown 先结束定时任务再删除目录。
- 补齐行为层回归，确保错误实现能使测试失败。类型检查、源码正则、配置包含断言保留各自用途，不替代行为验证。
- QB-04：逐条统一产品约束、当前实现与已实施状态，归档旧 utilityProcess 与未接入插件方案，修正文档中的发布排除和编辑器行为。
- QB-07：桌面输出干净构建，验证删除源文件后不再分发旧模块。测试产物规则与真实包清单分别验证。
- QB-01：迁移受支持 Electron，核对运行时依赖、BrowserView、preload、权限和 updater。先完成隔离桌面与签名测试，再讨论正式发布。

测试与文档同步贯穿每一批，不延后到最后集中补齐。每个修复附行为前后证据；性能改进比较相同输入的耗时、RSS/CPU/磁盘代价；结构改进比较责任归属、重复规则和变更影响。仅剩不影响行为的清理时，类型与相关回归足够，不为增加指标堆砌测试。
