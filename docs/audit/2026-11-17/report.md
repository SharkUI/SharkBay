## 审计结论

项目存在多类长期积累的工程问题，主要集中于跨模块契约不完整：文件创建与保存共用覆盖接口；安装任务嵌套调度；外部 API 的异步失败无人接收；用户、终端、请求与列表身份未贯通；内部管理文件与公共文件 API 使用不同路径规则；Git 与任务镜像对合法布局及删除语义处理不足。这些问题具有明确触发条件，不依赖近期事故是否再次发生。

主台账共 **29 项审计发现：P1 7 项、P2 19 项、P3 3 项**，未确认 P0。P1 包括 5 项直接功能或边界缺陷，以及 LAN 信任设计、Electron 上游支持两项风险；不意味着已发生攻击、数据损失或生产宕机。完整列表见 [发现台账](findings.md)，每项的触发链、位置、保护条件、证据与修复建议保存在专项报告。

测试工程另按四个横向主题整理，与上述台账的测试缺口和 QB-05/QB-06 交叉，不重复计入 29 项。已完成 **82/82 个测试文件、9751 行及 helpers 的团队全文审读**；实际执行的是经过副作用筛选的 **13 文件、104 测试**，均通过。三份类型检查也通过。测试通过的结论只覆盖这些检查，已复现的反例说明现有验证尚未约束所有重要业务行为。

依赖批量查询返回 **33 个包级告警**（npm等级Critical 4、High 23、Moderate 5、Low 1），与工程问题数量分开。结合版本副本和开发/构建/运行入口分诊后，新增QB-08依赖维护项；Electron已由QB-01记录，不重复计数，也未将全部告警当作产品可利用漏洞。

本报告服务于发现隐藏缺陷、减少工程债务并提高性能、可靠性、安全和可维护性。历史故障属于回归与同类问题检查的资料，不是本轮审计目标；本报告不推断本机或 103 的宕机原因。

## 范围 基线与方法

- 固定快照取自 Git archive，不把本次工作区未提交的计划或其他改动当成目标版本。279 个受控文件内容指纹见 [baseline.json](baseline.json)。
- 三个 subagent 分别审查安全/数据、资源/生命周期、状态/界面，并进行第二轮反证与测试补审；主审检查测试、依赖、构建、文档与调用图，重放核心反例并统一去重。
- 对 130 个生产 TypeScript 模块建立 7 入口 AST 导入图，结合注册表、命令、动态资源和全文符号引用确认用途。导入可达不等于符号实际执行，孤儿候选经过额外核查。
- 源码以模块、业务入口、跨模块流程和工程机制覆盖；深度包括全文、关键调用链与结构检查，详见专项覆盖。没有声称每个 UI 分支都已实际运行。
- 只运行受控临时数据上的模块反例和筛选测试。没有启动 SharkBay 或完整 ApplicationRuntime，没有真实索引、正式外部写操作、安装升级或 103 变更。
- 既有计划的工作区基线在本轮由用户明确指定的提交取代；其他隔离与操作限制继续保留。

## 共性根因

1. **命令只有数据形状，没有完整业务语义。** 新建与保存、审批与终端输入、任务标识与文件名、超时与取消之间缺少不可破坏的约束；schema 正确不足以保证操作正确。
2. **异步和资源所有权跨层断开。** 父任务等待调度子任务、timer 和网络 Promise 脱离调用方、两套聊天索引独立维护，正常路径可用而异常和竞争路径失效。
3. **边界保护没有统一应用。** 用户文件 API 有路径保护，内部协议/产物路径另行拼接；公开入口检查并不能替代下层最终写入检查。
4. **历史设计与实际接入脱节。** 部分模块与状态只剩测试，实施 tracker 却仍声明已接通；类型镜像、巨型业务文件和未退出兼容层进一步增加理解成本。
5. **测试验证对象与真实承诺不一致。** 源码正则、mock 成功、输出 marker 或可选 regex 相等可能证明局部写法，而没有证明取消生效、命令执行、文件保留与真实存储正确。

这些共性问题适合通过小批契约修复和回归治理，而不是同时重写架构或删除所有复杂状态机。

## 性能与可靠性基线

reader 主审重放：1 MiB / 4096 行约 8ms，观测峰值 RSS 57,950,208 字节；8 MiB / 32768 行约 39ms，峰值 RSS 68,141,056 字节；20 轮各 16 行生命周期通过。结果受 GC/JIT 与文件缓存影响，属于低负载模块基线，不能证明真实大仓库、整应用或长时间运行安全。

类型检查耗时约 1.18/1.05/0.59 秒；Vitest 104 测试总耗时 2.20 秒。以上是本轮检查环境记录，不作为产品响应性能指标。真实冷/热启动、GPU、多客户端、高输出 PTY、规模化 profile 和真实索引的延迟/吞吐/CPU/RSS 曲线尚待隔离集成环境；没有虚构整应用性能改善百分比。

后续按同一环境与负载比较改善前后，增加可控取消、失败恢复和业务不变量验证。代码质量以责任归属、重复规则和变更影响改善验收，文档以事实逐项对照验收。
